# 검증 결과 — 제출 항목·배점 변경

## 통과
- 프론트 프로덕션 빌드 및 변경한 주요 화면·유틸 ESLint 검사
- 프론트 Node 테스트 44개(배점 경계, 총 배점, 평균+가산점, Excel·인쇄 포함)
- 관련 백엔드 테스트 101개: 배점 API/저장/심사 상한/잠금, 기존 점수 저장, 필수 입력·파일·체크박스, 기간 경계, 첨부, 가산점
- V20 → V21 데이터 보존과 빈 스키마의 전체 마이그레이션
- 브라우저에서 매니저 로그인, 제출 항목 없는 프로그램 개설
- 브라우저에서 40·35·25 배점 저장 후 수정 화면 재조회(총 100점 유지)
- 로컬 백엔드 재시작 및 Flyway 21개 마이그레이션 검증

## 전체 테스트 이력과 후속 검증
- 앞선 전체 실행은 170개 중 168개 통과, 2개 실패였다.
- 후속 수정: evaluatorSeesOnlyEvaluableTeamsAndCountsAllApplicationMembers만 지원 종료·심사 진행 중 일정으로 준비하도록 변경했다. 공통 fixture와 제품 코드는 변경하지 않았다.
- 해당 메서드를 단독 실행하여 1개 테스트, 실패 0개로 통과했다. 임시저장 성공, 합계 16점/배점 20점, 제출·매니저 등록 팀 노출, 초안 팀 제외 및 직접 조회 404, 팀장 포함 3명, 첨부 개수와 지원서 조회까지 기존 검증문 전체를 통과했다.
- assigningEvaluatorReopensCompletedProgram은 사용자 요청에 따라 수정·재실행하지 않았다. 배정으로 종료 상태를 바꾸지 않는 현재 정책을 유지한다.
- 후속 수정 이후 전체 스위트는 재실행하지 않았다.

## 범위와 로컬 상태
- 지원자 제출·심사위원 점수 입력·잠금·내보내기는 자동 테스트로 검증했다. 해당 역할의 브라우저 전체 흐름은 수행하지 않았다.
- 브라우저 확인용 프로그램 두 개를 로컬에 남겼다: [검증] 제출 항목 없는 프로그램, [검증] 항목별 배점 40·35·25.
- 기존 실행 백엔드가 구 버전 API를 사용하여 배점이 10점으로 저장되던 현상을 확인했고, 재시작 후 원하는 배점을 재저장·재조회했다.
