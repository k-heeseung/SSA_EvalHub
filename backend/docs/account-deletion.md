# 계정 삭제와 프로그램별 심사 배정 삭제

## 계정 삭제

`DELETE /api/users/{id}`는 기존 관리자 API다. MANAGER는 EVALUATOR와 MEMBER만 삭제할 수 있고 MANAGER·SUPER_ADMIN 대상으로는 403을 반환한다. SUPER_ADMIN의 기존 삭제 권한은 유지한다. 존재하지 않는 ID는 404다. 권한은 controller의 `@PreAuthorize`와 `AccountDeletionService.canManagerDelete`로 검사한다.

심사위원은 `users.deleted_at`을 설정하고 상태를 INACTIVE로 바꾼다. DB 계정 행과 기존 배정·평가·점수를 삭제하지 않는다. 삭제를 재요청해도 기록을 물리 삭제하지 않는다. 일반 심사위원 목록에서 제외하고 로그인, 기존 JWT 인증, 신규 배정, 상태 재활성화와 안내 메일 재시도를 차단한다. 남아 있는 초대 메일의 임시 비밀번호는 제거하고 발송을 취소한다.

프로그램별 기존 배정과 평가 결과는 남기며, `UserResponse.name`·`AssignmentResponse.evaluatorName`·`EvaluatorSubmissionSummary.evaluatorName`은 `삭제된 심사위원`으로 표시한다. 이때 이메일은 빈 문자열로 반환하고 일반 사용자 응답의 연락처·소속도 표시하지 않는다. DB의 원본 값은 유지하며 이메일의 중복 등록도 계속 금지한다. PDF·엑셀·평가 상세는 표시 이름을 사용하고 기존 집계는 동일한 제출 점수를 사용한다.

`UserResponse.deleted`, `AssignmentResponse.evaluatorDeleted`로 삭제 여부를 제공한다. 전체 배정 매트릭스에는 삭제된 심사위원의 기존 배정 열을 표시해 확인·삭제할 수 있게 하되 새 배정은 허용하지 않는다. 지원자·매니저 등 다른 역할의 삭제는 기존 물리 삭제 동작을 유지한다.

심사위원 계정 삭제 확인 문구:

> 심사위원 계정을 삭제합니다. 로그인과 신규 배정은 차단되며, 기존 평가 기록과 결과는 유지됩니다.

## 배정 삭제

`DELETE /api/assignments/{id}`는 제출 여부와 무관하게 프로그램별 배정을 물리 삭제한다. 해당 배정의 제출·임시저장 평가와 점수는 DB FK cascade로 삭제되어 복구할 수 없다. 다른 배정·심사위원 계정·팀은 유지한다. 이후 결과 조회와 평균·순위는 삭제된 배정을 제외한다. 재배정은 새 배정으로 시작한다.

배정 삭제는 평가 저장과 같은 프로그램 행 잠금을 사용한다. 평가 저장이 먼저 배정을 조회했어도 프로그램 잠금을 얻은 뒤 배정이 이미 삭제됐다면 404로 거부한다.

프론트는 배정 상세와 전체 배정 매트릭스에서 제출 완료 상태의 삭제도 허용하고, 실제 삭제 전에 기록 복구 불가와 집계 변경을 안내한다. 스마트 재배정은 제출 완료 평가를 자동 해제하지 않는 기존 정책을 유지한다.

## 검증

`AccountDeletionIntegrationTests`는 삭제 대상 역할 제한, 지원자 물리 삭제, 심사위원 논리 삭제 후 기록·집계 보존, 삭제 계정의 로그인·JWT·신규 배정·재활성화·메일 재시도 차단, 부분 제출·전체 제출 배정의 물리 삭제 및 다른 심사위원 평가 보존을 검증한다.

스키마는 새 Flyway 마이그레이션으로 반영한다. V24는 정책 확정 전 로컬 검증에 먼저 적용되어 변경하지 않고, V25에서 최종 정책인 배정 물리 삭제에 맞게 기존 배정 스키마를 복원한다. V23의 계정 논리 삭제 컬럼은 유지한다.
